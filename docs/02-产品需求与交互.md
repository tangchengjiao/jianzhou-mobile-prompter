# 产品需求与交互

版本：0.1 方案；2026-10-26。界面方向已由用户选择第三张设计，后续按实际体验迭代。

## 用户和目标

用户本人主要用 iPhone 拍中文口播，希望继续使用开拍、剪映或系统相机。现有提词器的会员限制、显示不好调、语音跟随失准影响拍摄节奏。需要 iOS 和 Android 两个版本，优先 iOS，自用，不要求上架。

成功的结果是：开始一次录制前能很快把稿子放进来，镜头旁的文字清楚，临时停顿或重读时容易恢复，录完的视频仍有正常声音。不用“功能数量”代替这个标准。

## 产品范围

| 阶段 | 包含 | 通过条件 |
| --- | --- | --- |
| 交互原型 | 编辑/导入/本地稿库、阅读参数、匀速练习、倒计时、手动定位、悬浮效果演示 | 用户能完整走一遍，不需要理解技术术语 |
| iOS 自用首版 | 原生本地稿库、匀速阅读、画中画实验通过的拍摄组合、简单安装说明 | 目标 iPhone 的实际拍摄流程通过 |
| 中文跟读版 | 中文识别、已知稿件定位、停顿保持、重读恢复、手动接管 | 本人真实稿件连续试拍达到下述标准 |
| Android 自用版 | 本地稿库、普通悬浮匀速、无障碍悬浮跟读、中文模型、APK | 用户安卓手机与拍摄 App 分别通过 |

账号、收费、运营后台、模板商城、剪辑系统和全平台云同步不在首版。稿件先通过复制粘贴、TXT/Markdown 导入导出和系统分享互通。

## 用户路径

主流程：打开最近稿件 → 改稿/导入 → 准备悬浮提词 → 调字号与语速 → 启动 → 手动切换拍摄 App → 开始拍摄 → 暂停/重读 → 结束。

练习流程：打开稿件 → 全屏练习 → 倒计时 → 播放 → 上一句/下一句/点句定位 → 从头再来。

语音跟读流程：具备可用音频输入 → 检测中文识别能力 → 用当前稿件做短句校准 → 识别 → 局部定位 → 平滑移动。没有可用麦克风时不要显示“正在跟读”。是否能在另一个 App 录像时执行此流程属于真机结果，不属于界面开关的承诺。

## 页面和操作

### 稿件入口

沿用已选设计：见舟提词、小标题“这次，想讲什么？”，正文编辑是主内容；主按钮“准备悬浮提词”。全屏练习作为并列模式。最近稿件位于下方，避免先进入一个空的项目管理页面。

标题和正文都可直接修改。修改自动保存在设备；字数和时长由正文、设定语速实时计算。空稿不能开始提词；原稿不因自动断行被改写。

支持 UTF-8 TXT / Markdown。首版将 Markdown 当普通文本导入，尚不承诺复杂排版转换；如导入文件编码不合适，提示复制粘贴即可，不要求用户处理一堆编码选项。原型的保存位置为当前浏览器，原生版另用应用本地存储。

### 提词准备

上半部是真实阅读字号的预览，下半部保留两个最常用参数：字号与语速。默认参考 32 点、180 字/分，需本人试拍后调整，不将默认值当最佳值。

镜像和开始倒计时放进设置，不挤占主要画面。界面尽量说“字/分”，不让用户理解 px/s。语速的原生换算需以排版位置为准，字号变化保留当前阅读句。

苹果准备页显示画中画相关说明；安卓显示悬浮权限相关说明。只有实际可用能力才能启用。原型按钮明确为“演示悬浮提词”。

### 全屏阅读

深色背景、大字、当前句更亮，已读内容变暗。文字放在靠近镜头且不被系统相机孔遮挡的位置。底部只保留播放/暂停、上一句/下一句、从头开始与参数入口。

匀速先可用，语音模式后接入。点任一句即可暂停并定位，避免拖动长稿寻找位置。播放到末尾停止；再次播放从头开始。离开练习页或原型切到后台停止，避免用户回来发现位置已经跑远。

原型采用按字符进度推进句子高亮，用于验证阅读节奏；原生交付将进一步完善持续平滑滚动和阅读带位置。

### 悬浮阅读

安卓原生浮层可做拖动、缩放和点击控制，靠镜头停放。锁定模式需有明确的返回控制方式，不能锁住后无法恢复。

苹果使用系统 PiP 控件与位置能力，不把安卓浮窗的任意透明度、任意停放和自定义按钮全部照搬。画中画内被绘制成视频的“按钮”不天然可点击；首版优先映射系统播放/暂停、前后跳。

原型只展示屏幕内窗体，背景不伪装为已打开开拍或剪映。它没有相机、麦克风或原生画中画能力。

## 中文跟读的具体设计

不要求完全照稿逐字念。跟读首先找“你在稿件的哪个位置”，然后决定要不要移动。

1. 原文保留，建立“归一化字符 → 原文字号/句子位置”的映射。
2. 汉字按可定位字符处理，英文按词辅助，忽略不朗读的标点和备注。
3. 识别输出按最近一段文字处理；中间结果可能被改写，不能把每一次回调都当成全新追加文字。
4. 默认在当前位置附近匹配。暂停和短句改口不足以证明跳段时，保持当前位置。
5. 重复一句时，附近的上一句优先；远距离跳转需连续短语证据，避免遇到常见词就跳到远处。
6. 临时加话时停住；回到原稿后重新定位。匹配不确定时允许一键切匀速或点击某句接管。
7. 数字和中英混合用本人常见内容验证，例如“19.9 / 十九块九”“1980 / 一千九百八十”“AI / FDE”。同音仅作次要加分，不能凭一个同音字决定位置。

建议以 12 条本人常用口播组成首批材料：普通顺读、停顿、重读、短句改口、中英数字混合各覆盖几条即可。不要先扩充大量基本不会遇到的情况。

## 体验验收目标（尚非测试结果）

- 从已有稿件开始，到准备好阅读尽量控制在三步内；初次权限和首次语言资源单独计算。
- 字号范围至少覆盖 24–48 点，实际拍摄距离验证可读性；原生版必要时扩大范围。
- 正常中文顺读时，识别到定位的可见延迟目标为约 1 秒以内；以手机实测记录，不直接声称“实时无延迟”。
- 停顿 3 秒不继续向前跑；重读和临时加话后能回到正确位置，不能把“有识别结果”当通过。
- 手动暂停和定位应立即响应；当前句不得被底部控制区遮住。
- 录制至少持续一段常见 5 分钟口播，检查浮窗存活、录像声音和发热；再决定是否扩到 20 分钟。

## 数据与产品复杂度

原生稿件保存纯文本、标题、创建/修改时间、阅读设置和最后定位。双端的稿件交换使用简单 JSON / TXT；桌面工程导入只提取 `teleprompter.text` 和可转换参数，不携带整套画布素材。

不加入内容上传、在线识别和订阅。若以后确实需要在手机上直接拍，再独立讨论美颜、外接麦克风、画质等需求；它不是本轮默认交付的拍摄替代品。
